## P1 — Corrections *(all resolved)*

### P1-1 · Week 7 prose describes code that is not in the example

`chapters/week-07-dictionaries-and-sets.md:167` said:

> The `if category in categories` check handles update vs. first-time creation.

There was no `if category in categories` anywhere in the chapter. The project step uses
`categories.get(category, 0) + amount`. A learner who went looking for that check would not find it.

> **RESOLVED.** The bullet now describes `.get()` with a default. A new *"Adding to a Running
> Total"* section shows the explicit `if`/`else` version first, then collapses it into the `.get()`
> one-liner and explains why that is the idiom you will see in real code.

### P1-2 · Week 11 advertised CSV coverage that never appeared

`chapters/week-11-file-io.md:11` listed *"Working with CSV files using the `csv` module"* under
Topics. The chapter never mentioned `csv` again — no example, no exercise, no recap question. The
bonus chapter then set "Export to CSV" as a challenge with no prior exposure.

> **RESOLVED.** Added a *"CSV: One Row Per Record"* section: what the raw file looks like, a
> `DictWriter` / `DictReader` example, the `newline=""` gotcha on Windows, the fact that everything
> reads back as a string, and a plain-text / CSV / JSON decision table. Try It Yourself, What to
> Notice, Common Mistakes, Recap Questions, and the checklist were all extended to match.

### P1-3 · Week 1 advertised installation and editor setup that never appeared

`chapters/week-01-getting-started.md:10` listed *"Installing Python 3.13 and setting up VS Code"*
under Topics, but the chapter contained no installation steps, no download link, and no instruction
on how to actually run a file. A complete beginner could not start.

> **RESOLVED.** Added a *"Set Up Your Machine"* section: install links, the Windows *Add to PATH*
> checkbox, the macOS certificates step, verifying with `python --version` (and the
> `python` / `python3` / `py` fallbacks), installing VS Code plus the Python extension, and running
> a first `hello.py`. Common Mistakes, Recap Questions, and the checklist were extended to match.

### P1-4 · `if __name__ == "__main__":` was used everywhere and explained nowhere

It appears in `chapters/week-12-inheritance-and-final-project.md`, `budget_tracker_week8.py`,
`budget_tracker_week10.py`, and `budget_tracker_final.py`. No chapter and no glossary entry
explained it. It is the single most cryptic line in the final program.

> **RESOLVED.** Added a *"Why the Last Two Lines Look Like That"* section to Week 12, a glossary
> entry for `__name__`, and a new recap question. Glossary also gained **Module**, since the
> explanation depends on it.

### P1-5 · `add_expense` dropped `.strip()`, so whitespace became a category

`"   ".title()` is `"   "`, which is truthy, so pressing space-then-enter created a category named
`"   "`. This affected `week-06-lists-and-tuples.md:145`, `week-07-dictionaries-and-sets.md:139`,
`week-08-functions.md:213`, and `week-09-intro-to-oop.md:138`. Weeks 6 and 7 had no fallback at all.

> **RESOLVED.** All four now use `input(...).strip().title() or "Uncategorized"`, matching
> `budget_tracker_week8.py`. Week 6 and Week 7 gained a Common Mistakes bullet — Week 7's points out
> that skipping `.strip()` makes `"Food"` and `"Food "` two separate dictionary keys.

### P1-6 · `get_non_empty_text()` recursed without a base case

`budget_tracker_final.py` called itself on empty input, so holding Enter raised `RecursionError`
after ~1000 attempts. It was also inconsistent with `get_valid_amount()` directly above it, which
correctly used `while True`.

> **RESOLVED.** Converted to a `while True` loop. Verified by feeding the no-default prompt 1500
> consecutive empty lines — the program now keeps re-prompting and exits normally.

### P1-7 · `load()` crashed on a corrupt or older save file

`budget_tracker_final.py` only caught `FileNotFoundError`. A hand-edited or truncated
`budget_data.json` raised `json.JSONDecodeError`; a file written before a field was added raised
`KeyError` from `Transaction.from_dict`, which used `data["category"]` directly. The chapter's own
exercises produced both failures.

> **RESOLVED.** `load()` now also catches `json.JSONDecodeError` and `(KeyError, TypeError)`, each
> with its own message, in `budget_tracker_final.py` and in the Week 11 and Week 12 listings.
> `from_dict` uses `data.get("category", "Uncategorized")`. Verified against a valid file, a
> truncated file, a record with no `category`, and a file with no `owner` key.

### P1-8 · `Transaction.display()` changed signature between Week 9 and Week 12

Week 9 defined `display(self, index=None)`; Week 12, `budget_tracker_week10.py`, and
`budget_tracker_final.py` defined `display(self, index)`. A student carrying their Week 9 class
forward and calling `transaction.display()` got
`TypeError: display() missing 1 required positional argument`.

> **RESOLVED.** Standardised on the forgiving `display(self, index=None)` with the `prefix` guard
> everywhere, so the method works with or without an index.

## P2 — Consistency, coverage, and scaffolding

### P2-1 · Topics lists advertise syntax that is never demonstrated

| Chapter | Listed in Topics | Demonstrated? |
|---|---|---|
| Week 2 | `//`, `%`, `**` | No — only `+ - * /` appear |
| Week 3 | Nested conditionals | No |
| Week 6 | `pop()`, `sort()`, `insert()`, `min()`, `max()` | No — only `append()`, `remove()`, `len()`, `sum()` |
| Week 7 | Nested dictionaries, `.keys()`, `.values()` | No — only `.items()` and `.get()` |

**Fix:** add one small example per missing item (floor division and modulo are genuinely useful —
`total_minutes // 60` and `% 60`), or trim the Topics lists so they are an honest contract.

### P2-2 · Weeks 6-7 keep two sources of truth for the balance

`week-06-lists-and-tuples.md` and `week-07-dictionaries-and-sets.md` maintain both a `balance`
variable and a `transactions` list, updating them separately. They can silently disagree. Week 8
quietly replaces this with `get_balance(transactions)` and never says why.

**Fix:** either derive the balance from `transactions` from Week 6 onward, or keep the duplicate
deliberately and add a "What to Notice" bullet flagging the hazard, so that Week 8's refactor lands
as the payoff instead of an unexplained change.

### P2-3 · Negative-amount formatting regresses in Week 7

Week 6 prints transactions as `{sign}${abs(amt):.2f}` (`week-06-...:169`). Week 7 prints
`${amt:.2f}` (`week-07-...:150`), producing `$-45.00`. Week 8 changes it again. Three consecutive
weeks, three different formats for the same line of output.

**Fix:** standardise on one display format from Week 6 and keep it.

### P2-4 · No tests anywhere

There is no way to verify that a change to the three reference implementations still works. The
logic is easy to test — `get_balance`, `spending_by_category`, `to_dict`/`from_dict` round-trip —
and doing so would model a habit worth teaching.

**Fix:** add `tests/test_budget_tracker.py` using `pytest` or plain `unittest`, covering the pure
functions and the save/load round trip via `tmp_path`. Keep it small and readable; it becomes a
bonus lesson in itself.

### P2-5 · Reference apps cannot be smoke-tested

All three scripts block on `input()` immediately, so nothing can check they even start. There is no
way to run them in CI or demo them without typing.

**Fix:** add a `--demo` flag (or read from `sys.argv`) that seeds a few transactions, prints a
summary, and exits. Also lets an instructor project a working app in seconds.

### P2-6 · No project configuration or CI

No `pyproject.toml`, no linter config, no GitHub Actions workflow. A repo that teaches "clean
naming and clear structure" should show what enforcing that looks like.

**Fix:** add a minimal `pyproject.toml` (project metadata + `ruff` config) and a small workflow
that runs `ruff check` and the tests on push. Keep it to ~25 lines so it stays approachable.

### P2-7 · Glossary gaps *(partly addressed)*

`python_beginner_glossary.md` was missing many terms the chapters actually use.

> **PARTLY RESOLVED** as a side effect of the P1 work. Added: `__name__`, Module, Docstring,
> f-string, Indentation, Block, Namespace, Frame, Traceback, REPL, Context Manager, CSV, and `None`.

**Still open:** positional vs. keyword arguments, and linking the glossary from each chapter on
first use of a term (see P3-6).

### P2-8 · Instructor guide has gaps

`instructor_guide.md` has no answers for the bonus chapter's reflection questions, no note about
common misconceptions per week, and does not flag that the Week 12 chapter code and
`budget_tracker_final.py` have drifted apart (the reference adds `get_non_empty_text`, changes the
over-budget warning text, and reformats several lines).

**Fix:** add a bonus-chapter section, a short "what students usually get wrong" note per week, and a
line explaining the intentional differences between the chapter listing and the reference file.

### P2-9 · No lesson on reading a traceback

`chapters/bonus-challenges-and-tips.md` advises *"Read the error messages. Python's error messages
are actually helpful."* Nothing in the course ever shows a traceback or explains how to read one,
even though Week 11 is entirely about errors.

**Fix:** add a short "How to Read a Traceback" section to Week 11 (or Week 1): read bottom-up, the
last line is the error type and message, the line above it is your code.

### P2-10 · `pip` and virtual environments are never mentioned

Bonus challenge #4 asks learners to use `matplotlib`, which requires `pip install`. Nothing in the
repo explains `pip`, `venv`, or why you would isolate dependencies.

**Fix:** add a short "Installing a Package" note to the bonus chapter with `python -m venv .venv`,
activation on Windows and macOS/Linux, and `pip install matplotlib`.

### P2-11 · `.gitignore` does not ignore files the course creates

Running the app creates `budget_data.json`. Week 11's examples create `notes.txt`, `data.json`, and
`transactions.json`. A learner following along will see all of them in `git status`.

**Fix:** add `budget_data.json`, `notes.txt`, `data.json`, `transactions.json`, `.venv/`, `venv/`,
`.idea/`, and `.vscode/` to `.gitignore`.

## P3 — Polish

The plan says "5-8 hours per week" globally, but no chapter says how long it should take. Add an
estimate and a difficulty marker at the top of each chapter so learners can pace themselves.

### P3-2 · How to run a script is never shown in a chapter *(resolved)*

### P3-3 · Week 9 shows a dangling method outside a class
`week-09-intro-to-oop.md:70-73` shows `class Transaction: pass` followed by an unindented
`def display(self):` — syntactically legal but semantically confusing in a chapter about the
difference between a function and a method. Indent it into the class or drop it.

Add a `starters/` folder with a skeleton file per week (imports, function stubs, `TODO` comments) so

The longer chapters (Weeks 8, 11, 12) would benefit from a small anchor list under the title.

### P3-6 · Cross-link chapters to the glossary
First use of *mutable*, *scope*, *instance*, *iteration*, etc. should link to
`python_beginner_glossary.md`.

### P3-7 · `CONTRIBUTING.md` and issue templates
The README already names contributors. A short contributing guide plus a "chapter feedback" issue
template would make it easy for learners to report confusion — which is the highest-value feedback
this repo can get.

### P3-8 · Add a `LICENSE` link to the README *(resolved)*
> **RESOLVED.** `README.md` now links `LICENSE` in a License section.

### P3-9 · Consider a light-theme diagram variant

Add GitHub topics (`python`, `beginners`, `education`, `oop`, `curriculum`) and a short description
so the repo surfaces in search.
